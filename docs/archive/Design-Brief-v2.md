# 冻结的 v2 设计规范：需求管理系统

> 文档类别：历史归档。以下内容只用于 Phase 1–31 的历史回归，不得约束 Morfra v3；当前设计事实只以根目录 `Design-Brief.md` 为准。

## 0. 文档职责

- `Product-Spec.md` 是功能、数据、行为与验收标准的事实来源；本文档不得新增功能。
- 本文档是视觉语言、颜色职责、组件状态和可访问性规则的事实来源。
- 设计稿存在时，页面布局和视觉细节以设计稿为准；设计稿不得违反本文档的底层原则与语义 Token。
- 组件实现 MUST 通过语义 Token 取色，不得在组件内直接写 Hex、HSL 或 Tailwind 固定颜色。
- Schema 阶段色和选项色是项目数据，可保存具体颜色；它们是组件禁止写死颜色规则的唯一业务例外。

## 1. 设计方向

### 1.1 产品形态与目标

| 维度 | 方向 |
|---|---|
| 形态 | macOS 浅色桌面工具，界面型应用 |
| 核心任务 | 在高信息密度下快速扫描、编辑和流转实体 |
| 信息密度 | Compact，4px 步进；点击区、表单和警告不压缩 |
| 第一印象 | 克制、精确、有层次、可掌控 |
| 视觉骨架 | 暖白与纯白负责安静；低饱和紫负责结构；绿色负责主要动作 |

### 1.2 设计原则

- **DP-001 密度优先于装饰**：空间服务于信息和操作，不制造无功能留白。
- **DP-002 颜色是标注，不是容器**：业务状态优先使用图标、圆点、文字和细线；不把整行、整卡或整段区域染色。
- **DP-003 紫色负责结构，绿色负责焦点**：紫色是接近中性的结构层；绿色是唯一主要强调色，两者不得作为双主色平级竞争。
- **DP-004 灰色禁用**：背景、文字、边框、骨架屏、禁用态均不得使用灰色；使用暖白、墨色、低饱和紫或保留原色相的弱化态替代。
- **DP-005 语义先于色值**：组件只表达“操作、选中、危险”等职责；更换主题时只改 Token 映射，不逐页改色。
- **DP-006 单焦点原则**：同一组件或局部区域只允许一个高饱和视觉焦点，不同时出现鲜绿色和鲜紫色。

### 1.3 色彩占比

- 暖白、纯白、墨色约占界面 85%，构成内容和阅读基础。
- 低饱和紫约占 10%，承担结构、边框、选中背景和次级信息。
- 高饱和绿色控制在 5% 以内，只用于主操作、焦点、执行反馈和短暂交互。
- 红色、黄色只在对应业务或系统语义出现，不参与品牌装饰。

### 1.4 参考与反参考

- 正向：Linear 的紧凑密度、统一组件状态和低装饰比。
- 反向：大面积无功能留白、彩虹阶段条、整卡状态色、亮绿亮紫同时争抢焦点。

## 2. 信息架构与页面

### 2.1 全局结构

1. 顶栏：项目切换、搜索、筛选、排序、字段、应用设置、Schema 设置、对话框开关。
2. 主内容：动态 Schema 驱动的纵向分组看板。
3. 详情面板：实体属性、Tab 内容，可关闭、全屏、自适应宽度。
4. 对话区：独立第三栏，可拖拽宽度。
5. 应用设置：应用级偏好；含“外观”和“版本”。
6. Schema 设置：项目级数据结构；与应用设置独立。

### 2.2 页面清单

| 页面 | 目的 | 关联需求 |
|---|---|---|
| 看板主视图 | 扫描阶段分布、创建、排序、筛选和流转实体 | REQ-001~003, REQ-026 |
| 详情面板 | 编辑单条实体的属性和 Tab 内容 | REQ-004~008 |
| 应用设置 | 配置全局主题、模块覆盖和检查更新 | REQ-023, REQ-030 |
| Schema 设置 | 配置当前项目阶段、属性、Tab 和数据颜色 | REQ-025, REQ-028 |

### 2.3 布局底线

- 顶栏横跨视口，不随下方栏宽变化。
- 看板、详情、对话区遵循 Product Spec REQ-003 的宽度、拖拽和 480px/960px 规则。
- 详情面板接近 480px 时属性区从两列直接切为一列；Tab 文字不截断、不换图标。
- macOS 桌面端是唯一目标；移动端和平板端 N/A。

## 3. 三层颜色架构

### 3.1 基础色板（默认主题）

| Primitive | 默认值 | 用途限制 |
|---|---:|---|
| `palette.canvas` | `#FCFCFA` | 页面暖白底色 |
| `palette.surface` | `#FFFFFF` | 内容、卡片、表单 |
| `palette.ink` | `#2B2421` | 主要文字；带暖调，不是灰色 |
| `palette.green.600` | `#3F7A02` | 实心主操作、绿色文字；白字对比度 5.26:1 |
| `palette.green.500` | `#5B9F00` | 焦点环、进度、图标和短暂反馈；对纯白对比度约 3.28:1 |
| `palette.green.50` | `#F4FAEC` | 悬停、拖拽落点、新建草稿 |
| `palette.purple.700` | `#5D3A73` | 次级文字、结构强标记 |
| `palette.purple.500` | `#76558C` | 三级文字、普通图标 |
| `palette.purple.100` | `#E8DDF0` | 边框、分割、进度轨道 |
| `palette.purple.50` | `#F5EFF8` | 选中背景、浮层、结构区 |
| `palette.success` | `#2C7A63` | 完成、通过 |
| `palette.danger` | `#B3261E` | 错误、危险、阻塞、P0 |
| `palette.warning` | `#7A5200` | 警告、等待、P1 |

> 默认值是可执行起点。调整具体 Hex 时必须保持语义、无灰色原则和 WCAG 门禁，并同步本文档与代码 Token。

### 3.2 语义 Token

| Semantic Token | 默认映射 | 职责 |
|---|---|---|
| `background.canvas` | `palette.canvas` | 应用底层 |
| `background.surface` | `palette.surface` | 看板、详情、卡片 |
| `background.elevated` | `palette.purple.50` | 弹窗、菜单、设置预览 |
| `text.primary` | `palette.ink` | 正文、标题、关键数据 |
| `text.secondary` | `palette.purple.700` | 标签、辅助信息 |
| `text.tertiary` | `palette.purple.500` | placeholder、时间、弱信息 |
| `text.disabled` | `palette.purple.500` 的弱化态 | 禁用文字；不把黑色降成灰色 |
| `border.subtle` | `palette.purple.100` | 普通分割与卡片边界 |
| `border.strong` | `palette.purple.500` 的低强度态 | 输入框、弹窗、明确边界 |
| `action.strong` | `palette.green.600` | 实心主按钮 |
| `action.base` | `palette.green.500` | 焦点、进度、交互图标 |
| `action.soft` | `palette.green.50` | 悬停、编辑、新建、拖拽落点 |
| `context.strong` | `palette.purple.700` | 当前上下文和结构标记 |
| `context.soft` | `palette.purple.50` | 选中、激活、浮层结构 |
| `feedback.success` | `palette.success` | 成功、通过、完成 |
| `feedback.warning` | `palette.warning` | 警告、临期、等待确认 |
| `feedback.danger` | `palette.danger` | 错误、危险、阻塞、失败 |

### 3.3 模块 Token

- 模块 Token 默认引用语义 Token，例如 `board.row.selected.bg → context.soft`。
- 只有用户在 REQ-030 中开启“自定义此模块”后，模块 Token 才保存覆盖值。
- 模块没有覆盖值时必须继续跟随语义层；不得复制一份相同色值冒充覆盖。
- 组件只引用语义或模块 Token，不引用 Primitive。

### 3.4 硬性限制

- 灰色不进入默认色板或配色选择器；手动输入灰色必须拒绝保存。
- 普通文字与背景对比度 ≥4.5:1；大文字和非文本控件 ≥3:1。
- 红色只用于错误、危险、阻塞和 P0；黄色只用于警告、等待和 P1。
- 状态必须同时有文字、图标或形状，不能只靠颜色区分。
- 透明遮罩和阴影使用紫色或墨色倾向，不使用中性灰遮罩。

## 4. 模块配色规则

### 4.1 全局背景、文字、边框

- 页面为暖白，内容为纯白，浮层为极浅紫。
- 主要文字用墨色，次级与三级文字用深浅紫。
- 普通边框用浅紫；焦点边框用绿；危险边框用红。
- 默认表面不带彩色填充，层级通过白/暖白/极浅紫和轻阴影表达。

### 4.2 顶栏与导航

| 状态 | 表现 |
|---|---|
| 默认 | 暖白顶栏、浅紫分割、紫色图标 |
| 悬停 | 极浅绿背景 + 绿色图标 |
| 打开/激活 | 极浅紫背景 + 深紫图标 |
| 已配置未打开 | 紫色圆点或数字角标，不整块填色 |
| 主操作 | 实心绿色 |
| 危险操作 | 默认紫色，悬停或确认时转红 |

搜索框默认白底浅紫边框，聚焦变绿色。项目、筛选、排序和字段浮层使用极浅紫容器；当前项浅紫，动作项悬停浅绿。

### 4.3 看板

- 阶段标题统一使用主题 surface；Schema 阶段色仅以左侧细条或名称前圆点显示。
- 阶段默认色板优先提供绿紫深浅变体，不允许整条彩色阶段背景。
- 实体行默认白色；悬停极浅绿；选中浅紫背景 + 深紫细条；聚焦绿色焦点环。
- 拖动中保留色相并降低强度；拖拽落点极浅绿 + 绿色边框。
- 快速新建默认白色，仅加号、聚焦边框和草稿态使用绿色。
- 普通单选/多选颜色只显示为圆点或短条；标签主体保持白色或极浅紫。
- 冻结列必须继承整行状态，不能形成不同色块。

### 4.4 详情面板

- 面板纯白，与看板用浅紫分隔；拖拽手柄默认浅紫、操作时绿色。
- 属性区使用极浅紫结构背景；字段名紫色、字段值墨色、编辑聚焦绿色。
- Tab 默认紫色，悬停绿色，当前 Tab 为浅紫背景 + 深紫文字。
- 正文白底墨色；引用与代码块使用极浅紫；链接深紫、悬停绿色。
- 普通卡片白底浅紫边框；当前编辑绿色边框；新建草稿极浅绿；当前选中浅紫。
- 删除按钮默认紫色，只有悬停和危险确认使用红色。

### 4.5 业务状态

颜色只用于小图标、圆点、文字、细线或进度条，不用于整行、整卡背景。

| 语义 | 默认映射 | 非颜色信号 |
|---|---|---|
| P0 | danger | `P0` 文案 |
| P1 | warning | `P1` 文案 |
| P2 | context | `P2` 文案 |
| 待开始/未验证 | context | 空心圆 + 文案 |
| 进行中 | action | 进行图标 + 文案 |
| 完成/通过 | success | 对勾 + 文案 |
| 阻塞/不通过 | danger | 阻塞/叉号图标 + 文案 |
| 废弃 | context.strong | 归档图标或删除线 + 文案 |
| 临期 | warning | 日期文案 |
| 逾期 | danger | 日期文案 |

进度条轨道用浅紫，填充用绿色；100% 额外显示完成标识。

### 4.6 系统状态

- 加载：暖白区域 + 极浅紫骨架和低强度紫色微光；小型进度指示可用绿色。
- 空状态：紫色线性图标、墨色标题、紫色说明、绿色主引导。
- Toast：白色容器 + 语义色图标或左侧细条，不使用整块深色或整块语义色。
- 错误/警告：优先内联；白色容器配红/黄图标或细条，不染整块内容区。
- 禁用：彩色控件保留色相并降低强度；文字和图标用 `text.disabled`，同时提供禁用光标、锁图标或说明。
- 确认弹窗：白色/极浅紫容器；普通确认绿色；取消紫色；危险确认红色。
- 更新进度：浅紫轨道 + 绿色进度；失败仅用红色图标和文字。

### 4.7 对话区

- 容器纯白、浅紫分隔；输入框聚焦绿，发送按钮实心绿。
- 用户消息使用极浅紫背景；AI 回复白色或透明背景，不使用大面积绿色气泡。
- 思考中用紫色脉冲点；执行中用绿色进度；等待确认黄色；失败红色；中断紫色。
- 角色必须通过位置、图标或标签区分，不只依赖颜色。

### 4.8 Schema 自定义颜色

- 阶段和选项颜色属于项目数据，不由全局主题覆盖。
- 自动色板稳定轮询绿紫变体；分配后持久化，重排不改色，删除不重排其他颜色。
- 可选其他有彩色相但禁止灰色；红黄旁显示语义提醒。
- 自定义颜色只影响圆点、细条或小图标；不得铺满阶段标题、实体行或标签主体。
- 颜色过浅、与承载背景不可辨时阻止保存并说明原因。

## 5. 应用配色设置

### 5.1 页面结构

- 入口：顶栏“应用设置” → 左侧“外观” → “配色”。
- 中部：先编辑语义色，再按模块展开覆盖项。
- 右侧：综合预览顶栏、看板、详情、业务状态、系统反馈和禁用态。
- 底部固定操作：恢复默认、取消、应用。

### 5.2 行为规则

- 进入页面时复制当前主题为草稿；编辑只影响预览。
- 模块默认跟随主题；开启“自定义此模块”才保存覆盖。
- 单模块可恢复跟随主题；整套可恢复默认。
- 点击应用前执行灰色、保留色和对比度门禁；失败必须定位具体项。
- 点击取消完整恢复进入设置前主题。
- 配置为应用级全局偏好；切换项目不变，配置损坏时回退默认。
- 第一版不做命名主题、导入导出、主题市场、项目级主题或深色模式。

## 6. 组件与交互状态

| 组件/状态 | 统一规则 |
|---|---|
| Primary Button | `action.strong` 实底 + 白字；每个局部区域最多一个主按钮 |
| Secondary Button | 白底浅紫边框 + 深紫文字；悬停浅绿 |
| Ghost Button | 透明底紫色图标/文字；悬停浅绿 + 绿色 |
| Danger Button | 仅危险确认使用红色实底；普通入口默认紫色 |
| Input | 白底浅紫边框；聚焦绿色；错误红色并带文字 |
| Tab/Nav | 默认紫色；悬停绿色；激活浅紫背景 + 深紫文字 |
| Row/Card | 默认白色；选中浅紫；编辑绿色边框；状态色不铺满 |
| Checkbox/Switch | 未选紫色轮廓；已选绿色；部分选择紫色填充 |
| Focus | 2px 绿色焦点环，键盘可见，不因鼠标态移除可访问性 |

动效快而隐形，默认 ≤150ms；允许面板、Tab、浮层和草稿出现动画，不使用弹性、回弹或装饰性循环动画。支持 `prefers-reduced-motion`。

### 7.1 字体

- 主字体：Geist Sans，本地自托管。
- 等宽字体：Geist Mono，用于表头、计数、时间和结构化短值。
- 标题克制，不通过超大字号制造层级；主要靠字重、间距和位置。

### 7.2 间距与圆角

|---|---:|
| `space.xs` | 4px |
| `space.sm` | 8px |
| `space.md` | 12px |
| `space.lg` | 16px |
| `space.xl` | 24px |
| `radius.sm` | 6px |
| `radius.md` | 8px |
| `radius.lg` | 12px |

### 7.3 阴影

- 阴影只用于弹窗、浮层和必要的面板层级。
- 阴影使用低透明紫色/墨色倾向，不使用中性灰阴影。
- 普通卡片依靠白色表面和浅紫边框，不普遍加阴影。

## 8. 可访问性与验收

- 普通文字对比度 ≥4.5:1；大文字和非文本控件 ≥3:1。
- 所有可交互元素可键盘访问，焦点状态清晰可见。
- 表单字段有 label；错误信息与字段关联。
- 所有业务和系统状态同时提供文字、图标或形状，不只靠颜色。
- 禁用、未选择、只读三个状态必须可区分。
- 配色设置应用前使用相同标准做自动门禁。
- 仅浅色模式；macOS 桌面端；最小窗口规则遵循 Product Spec。

## 9. 实现约束

- 颜色结构固定为 Primitive → Semantic → Module → Component。
- Primitive 的具体值集中在单一 Token 文件；Semantic 和 Module 通过 CSS 变量映射。
- 组件禁止直接写固定颜色类、Hex、HSL 或复制语义值。
- 用户主题配置只保存基础/语义修改和显式模块覆盖；缺省覆盖不得落冗余值。
- Schema 阶段/选项颜色继续随项目数据持久化，与 AppThemeConfig 隔离。
- 设计审查时优先检查：是否出现灰色、是否整块状态填色、是否双高饱和焦点、是否绕过语义 Token、是否对比度失败。
