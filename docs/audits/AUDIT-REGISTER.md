## 3. 问题状态机

| 状态 | 含义 | 进入条件 |
|---|---|---|
| `待处理` | 问题已登记，尚未进入获批计划 | 审查证据成立且无需先做产品决策 |
| `待决策` | 事实已确认，但目标行为或文档存在冲突 | 明确记录待决策问题，不替用户选择 |
| `已规划` | 已进入获批开发计划 | 记录对应 Phase/任务链接 |
| `修复中` | 已由修复任务实际接手 | 记录任务/分支与负责人 |
| `已修复待验收` | 已有修复证据，但独立复验尚未通过 | 必须填写代码变更与测试证据 |
| `已验证` | 修复已被独立复验确认 | 必须同时存在代码变更证据与 code-review 复验通过证据 |
| `拒绝修复` | 经明确决策不实施 | 保留原因、决策人/依据和影响，不删除记录 |

正常流转为 `待处理 → 已规划 → 修复中 → 已修复待验收 → 已验证`；`待决策` 只能在决策写入产品事实源后转为 `待处理` 或 `拒绝修复`。修复 Agent 最多更新到“已修复待验收”，不得自行关闭问题；只有独立 code-review 复验通过后才能标记“已验证”。
