# AI 对话生成 Schema — 设计方案（二期）

> 文档类别：未来提案（基于冻结的 v2 Schema 模型）
>
> 不属于 Morfra v3 当前范围，不得作为当前实现或 AI 表格助手接入依据。若未来启动，必须先按 v3 的“项目 → 表 → 视图 → 记录/字段”模型重新立项、复核需求并生成独立 Product Spec 与 DEV-PLAN。

---

## 1. 定位

除了手动逐步新建属性/Tab，还支持"跟 AI 对话，描述想要管理什么（比如自媒体工作流），AI 推荐阶段、属性、详情页属性、Tab 的组合，一次性生成"。

关键判断：AI 生成 Schema 最终落地时，必须调用与手动操作相同的底层动作（新建阶段/属性/Tab），AI 只是替用户规划出一整套操作再批量执行，不是独立的另一套后门——所以手动增删改的能力必须先完整存在。

---

## 2. 技术定性：普通结构化生成，不是 Agent ✅

"一句话生成阶段/属性/详情页/Tab 组合"是一次性的结构化生成任务（自然语言 → 符合 Schema 格式的 JSON），不需要多步骤、带工具、边执行边看反馈的 Agent 架构。一次模型推理即可完成映射，走强制结构化输出（tool use / JSON mode）就够。

可选加强项：生成结果先本地校验（属性名重复、类型不合法等），不合法则把报错丢回模型重新生成一次，形成一个很窄的"生成→校验→重试"小循环——这不等于开放式 Agent，量级完全不同。

---

## 3. 模型接入方式 ✅

不绑定具体厂商。应用提供一个通用的"OpenAI 兼容接口"配置项，用户在设置里自己填 API Key + Endpoint（任何兼容 OpenAI 接口格式的服务商都能接，包括国内供应商）。

---

## 4. API Key 存储 ✅

不进现有的本地 Markdown 项目文件（会明文暴露，项目文件分享给别人时可能泄露）。使用系统密钥串/加密存储（Tauri 侧方案，如 stronghold 或系统 keychain），与项目数据分开存放。

---

## 5. 生成后先预览再确认 ✅

AI 推荐完一套 Schema 方案（阶段/属性/Tab 组合）后，先展示预览（列出将新增/修改的阶段、属性、Tab），用户确认后才真正写入 Schema、应用到看板和详情页。不做"生成即应用"。

---

## 6. 对话框模式切换 ✅

对话框保留原有的日常假聊天模式，同时提供一个明确入口切换到"生成 Schema"专属模式。专属模式下的对话专注于需求提取和方案预览，不与日常聊天混在一起，不需要模型自行判断意图。

---

## 7. 成本与频率控制 ✅

不做任何调用频次限制或用量提示。Key 是用户自己配的，调用成本由用户自行承担，保持实现简单。

---

## 8. 一句话如何变成完整 Schema 结构 ✅

以"帮我建一个管理自媒体工作流的看板"为例，走一遍完整流程：

- **多轮对话逆问，不是一句话一次性猜完**：AI 收到初始描述后，像需求访谈一样逐层反问关键问题（"发布渠道是单平台还是多个？""要不要跟踪审核状态？"），把阶段、属性、Tab 逐步问清楚，确定度足够后才生成方案。不追求"一句话包打天下"。
- **既能用于全新空项目（开局向导），也能对已经在跑、有数据的项目做增量改动**：不限定只能在项目初始化时用，用户随时可以在已有项目里说"帮我加个属性""帮我重新设计一下产出 Tab"，AI 基于当前 Schema 现状提出增量修改方案。
- **方案含删除/合并类操作时，预览内醒目标注风险，不另开二次确认弹窗**：AI 方案如果包含删属性/删 Tab/合并阶段选项这类会级联清值的操作，预览清单里对这些条目做醒目标注（提示不可恢复），用户确认预览本身即完成确认。
- **预览用文字清单式，不做所见即所得渲染**：预览呈现为人话描述的改动清单（例如"新建 3 个阶段：选题、剪辑、发布；新建属性：平台（单选）、发布链接（文本）…"），不在预览态真实渲染出看板/详情页效果。用户确认后才真正写入 Schema、应用到界面。

---

## 9. 用户自定义计算属性（随本方案一起交付）✅

通过 AI 对话创建计算属性，AI 生成计算逻辑后锁死。
- 引用范围：同实体其他属性 + 子 Tab 记录聚合，不跨实体
- 被引用属性删除时：计算属性报错（显示错误状态）
- 创建路径：只有 AI 对话，不能在 Schema 设置页手动写公式
