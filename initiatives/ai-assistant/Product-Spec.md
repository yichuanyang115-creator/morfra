## 1. 产品上下文

### 1.1 产品摘要

AI 表格助手是依附于单张表的本地桌面 AI 侧栏。用户可直接询问当前表中的数据、获得总结和分析，也可在同一张表下进行通用对话。表格事实由本地数据层读取和计算，云端模型负责理解问题、组织结论和解释结果。

第一版只读，不创建表格、不修改字段、不写入记录。

### 1.2 用户问题

一张表可以承载大量不同字段和记录，但用户要理解全局状态时仍需手动筛选、计数、比较并逐条翻看。现有右侧对话栏只有假回复，既不理解表格，也不能保留多条有组织的分析会话。

### 1.3 目标用户

| 用户类型 | 描述 | 核心需求 |
| --- | --- | --- |
| 本地个人管理者 | 独自在 macOS 应用中管理任务、需求或其他可表格化对象 | 不离开当前表即可提问、总结和分析，并能追溯结论对应的记录 |

### 1.4 核心价值

把“看表、筛选、计算、解释”收敛到当前表右侧：精确结果交给本地计算，开放问题交给模型理解，让用户得到可核对而不是看似聪明的答案。

### 1.5 成功标准

| 判断标准 | 目标 / 信号 |
| --- | --- |
| 表格事实可靠 | 固定评估集中的计数、筛选、分组、求和、平均值和引用记录全部与本地数据一致 |
| 无虚构数据 | 固定评估集中不得出现不存在的记录、字段或数值；信息不足时必须明确说明无法得出结论 |
| 路径完整 | 用户可从打开侧栏到获得带记录引用的回答，全程不离开当前表 |
| 会话隔离 | 切换表后只出现目标表自己的表格分析与通用对话历史 |
| 数据只读 | 任何 AI 请求、回答、重试或引用操作都不改变表结构与记录值 |

## 2. 产品原则

1. **忠于一张表**：表格分析与通用对话都归属于当前表，不存在项目级或应用级的独立聊天空间。
2. **只读优先**：AI 负责理解、总结和分析，不负责创建、修改或删除表格数据。
3. **本地算，模型讲**：精确统计由本地执行；模型不得自行心算表格数值。
4. **模式清楚**：表格分析受表内数据约束；通用对话可回答任意问题，并按问题类型自行判断是否读取当前表。
5. **来源可核对**：使用表格数据形成的结论必须能回到具体字段、记录或明确的计算范围。
6. **先做最小闭环**：第一版不解决图表、联网搜索、文件解析、跨表分析和数据版本追踪。

## 5. 用户流程

### FLOW-AI-001：首次配置模型服务

**关联任务：** TASK-AI-001

**入口：** 用户打开右侧 AI 面板，当前没有可用服务配置。

**主路径：**
1. 面板显示“配置 AI 服务”引导卡片。
2. 用户进入应用设置的“AI 服务”。
3. 用户填写配置名称、HTTPS Base URL 和 API Key。
4. 系统调用模型列表接口；成功时展示模型列表，失败时允许用户手填模型 ID。
5. 用户选择默认模型并测试连接。
6. 测试通过后保存配置，返回右侧面板开始对话。

**分支路径：**
- Key 无效、地址不可达、模型不存在或接口限流时，设置页就地显示可理解的原因。
- 模型列表不可用但对话接口可用时，用户可通过手填模型 ID 完成配置。

**完成状态：** 应用存在至少一组可用配置；API Key 只保存到 macOS Keychain。

### FLOW-AI-002：分析整张表

**关联任务：** TASK-AI-002

**入口：** 用户在当前表打开 AI 面板并创建“表格分析”会话。

**主路径：**
1. 面板显示当前表名称、记录数量与“整张表”范围。
2. 用户输入问题并发送。
3. 系统读取当前表最新 Schema 与记录，生成必要的本地分析计划。
4. 精确计算在本地执行，模型接收必要字段、相关记录与计算结果。
5. 回答流式显示，按需包含结论、关键数字、Markdown 表格和记录引用。
6. 用户点击记录引用，主区域打开对应记录详情，右侧会话保持不变。

**完成状态：** 用户获得可核对的只读回答，当前表没有被修改。

### FLOW-AI-003：分析已选记录

**关联任务：** TASK-AI-003

**入口：** 用户在表格中勾选一条或多条记录。

**主路径：**
1. AI 输入区显示“引用已选 N 条”。
2. 用户主动点击引用按钮，本次消息显示已选记录范围。
3. 用户发送问题，系统只使用这些记录完成本次分析。
4. 本次回答结束后，下一条消息默认恢复“整张表”。

**边界情况：** 记录在发送前已被删除时，从本次上下文移除；全部失效时阻止发送并提示重新选择。

### FLOW-AI-004：通用对话自动判断表格上下文

**关联任务：** TASK-AI-004

**入口：** 用户创建“通用对话”会话。

**主路径：**
1. 用户提出任意问题。
2. 系统根据问题类型判断是否需要当前表数据。
3. 纯通用问题不读取表格；明显涉及当前表的问题读取必要数据。
4. 一旦使用表格数据，仍执行本地精确计算并提供记录引用。
5. 无法判断时，系统才追问用户是否需要结合当前表。

### FLOW-AI-005：管理当前表会话

**关联任务：** TASK-AI-005

**入口：** 用户点击面板顶部“历史”。

**主路径：**
1. 面板内部切换为当前表的会话列表。
2. 用户可新建表格分析或通用对话，也可切换、重命名和删除已有会话。
3. 删除会话前二次确认，确认后永久删除。
4. 用户返回会话后继续提问。

**边界情况：** 删除模型配置不删除会话；该配置不可用时，会话提示更换模型后继续。

## 6. 产品形态

### 6.1 整体位置

AI 面板沿用主产品现有第三栏：位于表格 / 看板与详情面板右侧，由顶栏入口控制显隐。它不是弹窗，也不是独立页面。

```text
┌──────────── 主表格 / 看板 ────────────┬──────── AI 右侧面板 ────────┐
│                                       │ 表格分析｜通用对话  历史  × │
│ 用户浏览、筛选、勾选记录               ├─────────────────────────────┤
│                                       │ 当前范围：整张表 · 126 条   │
│ 点击引用后在主区域打开记录详情          │                             │
│                                       │ 对话内容                     │
│                                       │ 结论 / 数字 / 表格 / 引用   │
│                                       ├─────────────────────────────┤
│                                       │ [整张表] 输入问题…      发送 │
└───────────────────────────────────────┴─────────────────────────────┘
```

### 6.2 面板结构

1. **顶部栏**：当前模式、历史入口、新建对话、收起。
2. **上下文栏**：表格分析显示表名、整张表或已选记录、记录数量；通用对话按是否实际读取表格决定是否显示范围。
3. **消息区**：线性展示用户消息、回答块、生成状态和错误恢复操作。
4. **输入区**：多行输入、范围引用、低强调模型选择器、发送 / 停止按钮。

### 6.3 空白状态

- 未配置模型：显示配置引导，不显示不可用输入框。
- 已配置但无会话：显示当前表名称、记录数、模式切换、输入框与快捷问题。
- 快捷问题按字段能力出现，不允许针对不存在的字段生成入口：
  - 所有表：“总结这张表”。
  - 存在单选字段：“分析各选项分布”。
  - 存在日期字段：“查看时间安排和临期记录”。
  - 存在进度字段：“找出低进度记录”。
  - 存在已选记录：“总结已选记录”。
- 快捷问题点击后才发送，不自动调用模型。

### 6.4 正常回答

回答按需使用以下层级，不强制每次全部出现：

1. 直接结论。
2. 关键数字或简洁表格。
3. 分析说明。
4. 可点击的数据依据。

普通寒暄与简单问题使用普通文字消息，不套分析卡片。回答底部可提供最多 3 个追问建议，用户点击后才发送。

### 6.5 会话历史

- 历史列表在右侧面板内部展示，不打开新页面或弹窗。
- 只展示当前表的全部表格分析与通用对话。
- 会话标题根据首个有效问题自动生成，用户可重命名。
- 每条历史显示标题与模式标签，不显示模型、Token、耗时和费用。
- 模式是会话固定属性；切换模式等同于新建对应模式的会话。

### 6.6 响应式行为

- 宽屏：作为独立第三栏占据右侧并压缩中间内容；继续沿用可拖拽宽度。
- 窄屏：改为覆盖式右侧抽屉，避免把表格或详情压缩到不可用。
- 面板开关状态与宽度作为应用级偏好保存；切换表时保持显隐和宽度，只切换会话内容。
- 面板收起或用户浏览其他记录时，进行中的请求继续执行；完成后 AI 入口显示非打断式提示。

### 6.7 视觉继承

- 继承现有对话模块的主题变量、排版、圆角、间距和交互状态，不建立第二套视觉系统。
- 不新增自由配色，不使用灰色作为界面颜色；具体颜色继续服从主产品设计稿、Design Brief 与主题门禁。

## 7. 功能需求

### REQ-AI-001：模型服务配置

**优先级：** P0

**关联任务：** TASK-AI-001

**关联流程：** FLOW-AI-001

**规则：**

- MUST 支持保存多组服务配置，每组包含名称、HTTPS Base URL、默认模型和模型列表缓存。
- MUST 以 OpenAI 兼容协议调用 `GET /models` 与 `POST /chat/completions`。
- MUST 使用 Bearer API Key；第一版不支持自定义认证头、查询参数认证或 OAuth。
- MUST 支持模型列表加载失败后的手动模型 ID。
- MUST 在保存前测试对话能力；流式、结构化输出和工具调用属于能力探测，不作为全部模型的硬性要求。
- MUST 在流式不支持时退化为一次性返回。
- MUST 在结构化输出或工具调用不支持时使用普通 JSON 协议、本地校验和有限重试；仍无效则停止并提示模型不兼容。
- MUST 将 API Key 存入 macOS Keychain；前端只持有配置 ID 和“已配置密钥”状态。
- MUST 支持删除服务配置，并同步删除对应 Keychain 项；删除前二次确认。
- MUST NOT 自动推断模型价格、上下文窗口、质量等级或完整能力。

**验收标准：**

- [ ] AC-AI-001：Given 用户填写可用兼容地址和 Key，when 测试连接并保存，then 模型列表可选且 Key 不出现在本地普通配置文件中。
- [ ] AC-AI-002：Given `/models` 不可用但模型 ID 可用，when 用户手填模型并测试，then 配置可以保存并完成一次对话请求。
- [ ] AC-AI-003：Given Key 无效、地址错误、模型不存在、限流或断网，when 测试连接，then 设置页显示对应可恢复原因且不保存为可用状态。
- [ ] AC-AI-004：Given 用户删除服务配置，when 二次确认，then Keychain 项被删除而历史会话仍保留。

### REQ-AI-002：按表隔离的多会话与双模式

**优先级：** P0

**关联任务：** TASK-AI-004、TASK-AI-005

**关联流程：** FLOW-AI-004、FLOW-AI-005

**规则：**

- MUST 每条会话归属于且只归属于一个稳定 `tableId`。
- MUST 同一表支持多条表格分析和通用对话。
- MUST 会话模式创建后固定；切换模式创建新会话。
- MUST 新会话不继承其他会话消息，但可读取所属表的最新数据。
- MUST 用户可切换当前会话后续消息所用的服务配置和模型；已有消息保持原样，每条助手消息保存实际模型引用但正常界面不展示技术元数据。
- MUST 切换表后加载目标表历史，不显示来源表会话。
- MUST 支持新建、切换、自动标题、重命名和删除。
- MUST 会话删除前确认，删除后不可恢复。
- MUST 表删除时级联删除其全部 AI 会话。

**验收标准：**

- [ ] AC-AI-005：Given 表 A 与表 B 各有会话，when 从 A 切换到 B，then 面板显隐和宽度保持，但只显示 B 的历史与当前会话。
- [ ] AC-AI-006：Given 当前会话是表格分析，when 用户切换到通用对话，then 系统新建通用会话而不是修改旧会话模式。
- [ ] AC-AI-007：Given 用户删除一条会话，when 确认删除，then 该会话从本地历史中永久移除，其他会话不受影响。

### REQ-AI-003：表格上下文与自动路由

**优先级：** P0

**关联任务：** TASK-AI-002、TASK-AI-003、TASK-AI-004

**关联流程：** FLOW-AI-002、FLOW-AI-003、FLOW-AI-004

**规则：**

- MUST 表格分析默认读取整张表最新数据，不受当前页面筛选、搜索、分组或视图类型影响。
- MUST 只有用户点击“引用已选 N 条”时，当前消息才限定为已选记录。
- MUST 已选记录范围只影响当前消息，下一条恢复整张表。
- MUST 通用对话按问题类型自动判断 `不读取表格 / 读取整张表 / 使用用户明确引用的记录`。
- MUST 用户明确引用范围时优先于自动判断。
- MUST 无法判断时追问，不得静默编造表格上下文。
- MUST 每次新提问读取最新数据；历史回答不自动修改。

**验收标准：**

- [ ] AC-AI-008：Given 当前页面只显示筛选后的记录，when 用户在整张表范围提问总数，then 结果基于表的全部记录而不是当前筛选结果。
- [ ] AC-AI-009：Given 用户只勾选记录但未点击引用，when 发送问题，then 系统仍使用整张表。
- [ ] AC-AI-010：Given 用户主动引用 3 条记录，when 发送问题，then 本次分析只使用 3 条，下一次输入恢复整张表。
- [ ] AC-AI-011：Given 通用问题与表格无关，when 发送，then 不读取表格；Given 问题明显指向当前表，then 使用必要数据并遵守引用规则。

### REQ-AI-004：本地确定性分析

**优先级：** P0

**关联任务：** TASK-AI-002、TASK-AI-003

**规则：**

- MUST 由本地引擎执行筛选、计数、分组、求和、平均值、最值、排序和空值判断。
- MUST 根据字段类型验证运算是否合法，不允许对文本执行数值求和等无效操作。
- MUST 对模型产生的分析计划做 Schema 校验；字段、选项、记录不存在时拒绝执行并有限重试。
- MUST 只向云端发送回答所需的字段、相关记录与本地计算结果，不无条件上传整张表。
- MUST 区分直接数据、确定性计算和模型推断。
- MUST 数据不足、冲突或无法支持结论时明确说明无法得出结论。
- MUST NOT 让模型直接生成未经本地校验的统计数值。

**验收标准：**

- [ ] AC-AI-012：Given 固定测试表，when 询问计数、占比、求和、平均值和分组，then 结果与本地直接计算完全一致。
- [ ] AC-AI-013：Given 模型返回不存在字段或非法运算，when 本地校验，then 不执行错误计划、不展示猜测值，并触发有限重试或兼容错误。
- [ ] AC-AI-014：Given 数据不足以判断原因，when 用户要求结论，then 回答明确标注数据不足，不虚构表内事实。

### REQ-AI-005：回答与记录引用

**优先级：** P0

**关联任务：** TASK-AI-002、TASK-AI-003

**规则：**

- MUST 支持普通文字、列表、Markdown 表格、关键数字和记录引用。
- MUST 所有基于表格记录的关键结论提供来源记录或明确的计算范围、记录数和字段。
- MUST 记录引用使用主标题字段显示，并携带稳定 `recordId`。
- MUST 点击引用后由主产品打开对应记录详情，AI 面板和会话不被卸载。
- MUST 回答中的外部链接默认不赋予本地能力，不执行模型生成的脚本或 HTML。
- MUST NOT 展示 Token、耗时、费用或模型内部运行信息。

**验收标准：**

- [ ] AC-AI-015：Given 回答引用现有记录，when 点击记录标题，then 主区域打开对应详情且右侧回答仍在原位置。
- [ ] AC-AI-016：Given 回答包含 Markdown 表格和列表，when 流式完成，then 内容可读且不执行原始 HTML 或脚本。
- [ ] AC-AI-017：Given 回答使用表格事实，when 检查来源，then 引用的记录 ID、字段和计算范围均可在本地数据中验证。

### REQ-AI-006：右侧面板与输入交互

**优先级：** P0

**关联任务：** TASK-AI-002、TASK-AI-004、TASK-AI-005

**规则：**

- MUST 保留现有顶栏开关、独立第三栏和拖拽宽度能力。
- MUST 面板内部按 §6.2 组织，不把 Base URL、Key 等配置表单塞入对话区。
- MUST 模型选择器低强调显示在输入区，按服务配置分组展示模型。
- MUST 支持 Enter 发送、Shift+Enter 换行、空内容禁止发送。
- MUST 窄屏使用覆盖式抽屉，宽屏使用独立第三栏。
- MUST 面板开关与宽度跨表保持，切表只更换会话数据。
- MUST AI 生成期间允许用户浏览表格与详情。

**验收标准：**

- [ ] AC-AI-018：Given 面板打开，when 用户拖动宽度或切换表，then 宽度与显隐保持且目标表会话正确加载。
- [ ] AC-AI-019：Given 视口不足以同时容纳三栏，when 打开 AI，then 面板以右侧覆盖抽屉出现，表格不被压缩到不可操作。
- [ ] AC-AI-020：Given 用户点击记录引用或浏览其他记录，when AI 正在生成，then 请求继续且会话不被卸载。

### REQ-AI-007：生成控制与失败恢复

**优先级：** P0

**关联任务：** TASK-AI-006

**规则：**

- MUST 模型支持流式时逐步显示，不支持时一次性返回。
- MUST 生成期间将发送按钮切换为停止操作。
- MUST 停止后保留已生成内容并标记为已停止，不继续写入后续片段。
- MUST 失败时保留用户原问题，并提供重试和更换模型。
- MUST 收起面板时请求继续；完成后顶栏 AI 入口显示非打断式完成提示。
- MUST 同一会话同一时间最多存在一个生成请求，避免消息顺序错乱。
- MUST 支持复制完整回答。

**验收标准：**

- [ ] AC-AI-021：Given 正在流式生成，when 用户停止，then 新片段不再进入消息且输入区恢复可用。
- [ ] AC-AI-022：Given 请求失败，when 用户重试，then 原问题无需重新输入且会话中不产生重复用户消息。
- [ ] AC-AI-023：Given 面板在生成中被收起，when 请求完成，then 会话完整保存且入口出现完成提示。

### REQ-AI-008：本地存储与删除

**优先级：** P0

**规则：**

- MUST 服务配置元数据与面板偏好应用级保存，API Key 单独进入 Keychain。
- MUST 会话、消息、模式、标题、模型引用和记录引用按 `tableId` 本地保存。
- MUST 应用不建立自己的 AI 云端同步、账号或后台。
- MUST 删除模型配置不删除历史会话；历史会话可更换模型后继续。
- MUST 设置中提供“清空全部 AI 对话历史”，二次确认后删除全部表的会话，不删除表格数据与模型配置。
- MUST 普通诊断日志不记录 API Key、完整请求正文或完整表格数据。

**验收标准：**

- [ ] AC-AI-024：Given 应用重启，when 重新打开某张表，then 该表会话、标题和当前会话恢复，其他表会话不混入。
- [ ] AC-AI-025：Given 用户清空全部 AI 历史，when 二次确认，then 所有会话删除，模型配置、Keychain 和表格数据保持不变。
- [ ] AC-AI-026：Given 检查普通配置文件与日志，when 搜索 API Key，then 不存在明文 Key 或完整请求正文。

### REQ-AI-009：状态与错误呈现

**优先级：** P0

**规则：**

- MUST 区分未配置、空表、无会话、准备数据、生成中、已完成、已停止、失败状态。
- MUST 空表时禁用表格分析发送并允许切换通用对话。
- MUST Key / 地址无效直接引导到对应配置。
- MUST 断网、限流、模型不存在和模型不兼容使用不同的可理解文案。
- MUST 错误在当前消息或设置区域内联展示，不打开独立错误页，不直接暴露底层错误栈。

**验收标准：**

- [ ] AC-AI-027：Given 当前表没有记录，when 打开表格分析，then 显示空表说明且通用对话仍可创建。
- [ ] AC-AI-028：Given Key 无效，when 发送问题，then 当前问题保留并提供进入对应配置的操作。
- [ ] AC-AI-029：Given 模型多次返回无效分析计划，when 重试上限耗尽，then 明确提示该模型不兼容本次分析且不输出猜测答案。

## 8. AI 能力规格

| AI 功能 | 能力类型 | 质量条 | 触发方式 | 不确定时 | 服务降级 |
| --- | --- | --- | --- | --- | --- |
| 表格问题理解 | 文本理解与结构化抽取 | 固定评估集的字段、运算和范围解析不得导致错误本地执行 | 用户主动发送 | 追问范围或说明无法判断 | 结构化输出 → JSON 协议 → 不兼容提示 |
| 表格总结与分析 | 文本生成 + 本地计算结果解释 | 数值与引用必须 100% 通过本地校验；不得虚构表内事实 | 用户主动发送 | 明确数据不足、区分事实与推断 | 流式 → 一次性返回；失败保留问题可重试 |
| 通用对话上下文判断 | 文本分类 / 理解 | 明确通用问题不得无故读取表格；明确表格问题必须进入表格规则 | 用户主动发送 | 只在无法判断时追问 | 不读取表格并请求用户澄清 |
| 会话标题与追问建议 | 文本生成 | 不得改变原问题与回答事实；失败不影响主回答 | 首条消息完成后 / 回答完成后 | 使用首条问题截断作为标题；不显示建议 | 静默退化 |

**AI 护栏：**

- 不得创建、修改、删除表结构与记录。
- 不得把模型常识写成表内事实。
- 不得输出未经本地校验的精确统计值。
- 不得在用户未发起问题时后台上传表格数据。
- 不得跨表读取或混用会话上下文。
- 不得记录、回显或发送其他服务配置的 API Key。
- 不得在信息不足时补造记录、字段、状态或时间。

## 9. 数据模型

### 9.1 核心实体

| 实体 | 描述 | 关键字段 |
| --- | --- | --- |
| AIProviderConfig | 应用级模型服务配置，不含 Key 明文 | id, name, baseUrl, defaultModelId, cachedModelIds, capabilityStatus |
| AIProviderSecret | Keychain 中的密钥引用 | providerConfigId, keychainService, keychainAccount |
| AIConversation | 归属于单表的一条会话 | id, tableId, mode, title, providerConfigId, modelId, createdAt, updatedAt |
| AIMessage | 会话内的线性消息 | id, conversationId, role, contentBlocks, contextRef, providerConfigId, modelId, status, createdAt |
| AIContextRef | 某条用户消息使用的数据范围 | type(fullTable/selectedRecords/none), recordIds[] |
| AIAnswerBlock | 可渲染回答块 | type(markdown/metrics/table/recordRefs), payload |
| AIAnalysisPlan | 经校验后交给本地引擎的分析计划 | filters, projections, groupBy, aggregates, sort, limit |
| AIPanelPreference | 应用级面板偏好 | open, width, lastProviderConfigId, lastModelId |

### 9.2 实体关系

| 关系 | 说明 |
| --- | --- |
| Application has many AIProviderConfigs | 多组服务配置应用级共享 |
| AIProviderConfig has one AIProviderSecret | Key 只通过配置 ID 关联 Keychain |
| Table has many AIConversations | 两种模式的会话都忠于一张表 |
| AIConversation has many AIMessages | 消息线性排列，不做分支 |
| AIMessage has zero or one AIContextRef | 纯通用问题可不读取表格 |
| AIMessage has many AIAnswerBlocks | 回答可组合文字、数字、表格和引用 |

### 9.3 生命周期规则

- 新建会话：必须有 `tableId`、模式和可用模型；标题在首条有效问题后生成。
- 更新会话：发送消息、重命名、切换后续模型时更新 `updatedAt`；模型切换不改写既有消息的模型引用。
- 删除会话：二次确认后永久删除消息与引用。
- 删除表：主产品必须调用 AI 清理接口级联删除该表会话。
- 删除模型配置：删除 Keychain 项与配置；会话保留原模型引用并进入“需更换模型”状态。
- 清空全部历史：删除全部表的会话与消息，不删除面板偏好、模型配置和表数据。
- 历史回答：保持生成时文本，不做数据版本追踪或自动重算。
